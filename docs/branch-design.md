# 分支剧本 · 节点编辑器设计图纸

> 版本 v0.2 · 2026-10 · 配套交互稿：`docs/node-editor-mockup.html`（浏览器直接打开体验）
> v0.2 变更：画布改为对称布局（无支线概念）、节点可在画布上展开为完整编辑卡（状态持久）、缩放改为「相机推进进卡片内部」、连线全量虚线

## 1. 目标

把「一天的剧本」从线性列表升级为**有向图**：

- 选项之间可以互相影响：不同选择走向不同的后续（支线）
- 支线可以**合流**回同一个节点，也可以一路走到底成为**不同结局**（不同的夜）
- 编辑体验遵守一个原则：**看结构用画布，改内容用单行**。单行排版是唯一编辑场所

## 2. 数据模型

```
preset = {
  id, name,
  start: 'n1',              // 入口节点
  nodes: {                  // id → 节点（无序，画布坐标只存布局）
    n1: {
      id, x, y,             // 画布坐标（编辑器布局用，运行时无关）
      kind: 'moment',       // moment 决策时刻 | passage 过场 | ending 终章
      time, title, bgKey,
      narration, photo,
      intros: [...],        // 时刻前的过场序列（不变）
      choices: [
        { text, delta, feedback, reflect, effect,
          next: 'n2' }      // ★ 新增：选它之后走到哪个节点
      ],
    },
    p1: { kind: 'passage', time, title, text, photo, next: 'n3' },
    e1: { kind: 'ending', time, title, note },   // 终章：跳转夜记
  },
}
```

要点：

- **`choice.next` 是唯一的分支表达**。不填 = 顺延（按画布/时间顺序的下一个节点）——这样**旧线性剧本零迁移成本**：线性列表本身就是一张每个节点只有单一下游的退化图
- 合流 = 两条边的 `next` 指向同一个节点，天然支持
- ending 节点 = 不同的夜记入口（可各自配一版开头/结尾文风）
- 预留（v0.2）：边上加条件，如 `cond: { gloomMin: 50 }` ——「阴霾 ≥50 才会出现的那条路」，对应最初构想里"失控后要付出更多努力"

## 3. 视图与交互

### 3.1 节点总览（画布：结构 + 就地编辑）

- **对称布局，没有「支线」概念**：自动布局把所有分支同等对待——分叉沿中轴线左右对称展开，合流点回到中轴。UI 语言里只有「节点 / 走向 / 合流 / 结局」，不区分主线与支线
- 节点两种形态，随时切换（⤢ / ⤡）：
  - **小卡**：时刻 + 标题 + 类型
  - **完整编辑卡**：在画布上直接展开该节点的全部编辑内容（旁白、过场、选项、走向），**展开状态持久保存**——玩家可以把整个剧本以"全部展开"的样子留在画布上
- 连线**全量绘制、统一虚线**：每条边 = 一个选项（或过场）的走向；选项边标注选项文字；隔行直达的边向外侧弯出，避免穿越
- 结局节点虚线卡；合流节点带「N 路合流」徽标

### 3.2 节点内部（聚焦编辑视图）

- 点按节点本体 → 相机推进，进入**该节点内部**：
  - 上半部分 = 这个节点自己的完整编辑卡（与画布展开形态同构，只是更大更疏朗）
  - 向下 = 「默认走向 ↓」接续的后续节点链（在这里继续编辑后续内容）
- 每个选项行的 **「→ 走向 ↗」** 可点击跳到目标节点内部
- 选项行 **「⋯ 分出新节点」**：从这条边长出一段新剧情；之后可把它的走向指回任意已有节点（合流）
- 左上角 **「‹ 节点总览」** 返回画布

### 3.3 相机推进（zoom-into-card）

不是"打开卡片变成页面"，而是**放大聚焦到卡片里面**。动效三条铁律（保证全程丝滑、零姿态跳变）：

1. **推近**：整幅画布以被点卡片为中心做 transform 缩放（≈2.2×，450ms），其余节点淡出失焦
2. **等比归位**：内部内容不直接以 1× 出现，而是**从放大的姿态（scale≈1.32）等比缩小归位**（380ms）——与推近方向连成一次连续缩放，消除"啪一下"的跳变
3. **驻留 + 直接缩小**：进入后画布**保持缩放姿态驻留**（绝不复位）；退出时内容反向放大淡出，同时相机从驻留姿态**直接缩小回全景**——别的节点一次连续缩小，没有任何幕后重摆
4. **展开⇄收起也是动画**：⤢/⤡ 切换时高度/位置/宽度带过渡，相邻节点平滑让位；连线先淡出、布局稳定后重绘再淡入，避免错位

技术上是对画布容器做单次 `transform: translate() scale()`（origin 在被点卡片中心），合成器动画，不掉帧；画布布局坐标不受影响。

## 4. 运行时（舞台）改动

- `nextUp / settle` 从"时间排序的下一个未玩场景"改为**沿图行走**：做出选择后，下一时刻 = 该选项的 `next`（不填则顺延）
- 一天的进度 = 一条走过来的路径；汇总页时间轴显示**实际走过的路径**
- 真实模式：只有**当前前沿节点**参与时间门控与"错过"判定；没走到的支线不存在时间概念
- 夜记：按路径快照生成（现有 snap 机制天然支持，不同结局配不同结尾文风）

## 5. 迁移

一次性把 `scenes[]` 转成 `nodes{}`：链式连接，每个选项 `next` = 下一场景 id，末节点接一个默认 ending。旧存档读入时自动执行。

## 6. 分期

| 阶段 | 内容 | 说明 |
|---|---|---|
| P1 | 图数据结构 + 舞台沿边行走 + 单行编辑里的「走向/分出支线」 | 结构就位，编辑仍在单行里完成 |
| P2 | 节点画布总览 + FLIP 无缝缩放 | 本次交互稿验证的体验 |
| P3 | 自动布局优化、手动拖拽、条件边（阴霾门控支线）、多结局夜记 | 锦上添花 |

## 7. 开放问题（需要你拍板）

1. **真实模式的分支语义**：到点只解锁"当前节点"，分支时间各自标注即可？（推荐）
2. **跨天记忆**：今天走的是支线 A，明天默认从哪开始——主线起点固定，还是"接着上次的生活"？
3. **条件边**（阴霾 ≥50 才出现的选项）要不要进 P1？它和你的核心数值机制最贴
